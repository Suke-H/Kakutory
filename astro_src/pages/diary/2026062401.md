# コードエージェントを作ってみた



最近、AIによってものづくりが相当に捗るようになった。特に思うこととして、**ツール**を作るハードルが下がった。

自分の周りで言うと、ゲーム制作に関する補助的なエディタ（パズルステージエディタ、ノベルエディタ等）であったり、Slack,  Discord の Bot 作成などなど。
「これツール化できるのでは？」の思いつきでツールが作れるようになったなと思う。  
私生活でも仕事でもここに億劫な人間だったのが、多少はモチベが沸くようになり嬉しい。

AIを使ったツールづくりを考えると、こういう種類があると思う。

1. AIとツールを作る
   - AIとコードを書く

2. ツールにAIを組み込む
   - LLM を組み込む
   - （+α）エージェントを組み込む

3. AI自体をツールにする
   - Skills

2については Anthropic のこういう記事を見て知った：[Building Effective AI Agents \ Anthropic](https://www.anthropic.com/engineering/building-effective-agents)

「LLM を組み込む」は、例えば Github でPRを出したときに動くコードレビューBotとか、そういう感じである。

じゃあ「エージェントを組み込む」とは何なのか。エージェントという単語自体よく聞くが、改めて考えると定義が分からない。そもそも作れる存在なのか。気になったので、調べたり作ったりしてみた。

## LLM とエージェント

先ほどの Anthropic の記事によると、LLM とエージェントはこういう定義らしい（以下、日本語訳）。

- LLM：入力を受け取って出力を返す基盤モデルそのもの
- エージェント：LLMが自らのプロセスとツール使用を動的に指示し、タスクの達成方法を自律的にコントロールするシステム

そしてこう書いてある。

> より複雑な処理が必要な場合、ワークフローは明確に定義されたタスクに対して予測可能性と一貫性を提供しますが、大規模な柔軟性とモデル駆動型の意思決定が必要な場合は、エージェントの方が適しています。ただし、多くのアプリケーションでは、検索とコンテキスト内の例を用いて単一のLLM呼び出しを最適化するだけで十分な場合がほとんどです。

ふむ。基本は LLM でいいらしい。ただ、エージェントの「自律的」とは何なのか。LLM との違いがよくわからない。

### エージェントを組み込む

一方エージェントが必要なタスクは、一往復のやり取りでは済まず「会話のループ」が必要なタスク。

ここでいう会話とは、**人間・ツール・自分自身**と会話することであり、会話ループの終了条件はLLM が「**タスクを達成できた！**」と判断したときである。これを「自律的」と言っているようだ。

### LLMとの会話はめんどう


作る際の補足を1つ。  
LLM は API だ。つまりステートレス。会話をするときは、毎回**入力にこれまでの会話を入れないといけない**（出力は大丈夫）。

実際のところ、こんな会話例になる：

```sh
[input]
- User: Pythonで〇×ゲームをgame.pyに作って

[output]
- AI: 作るね
- AI: write_file(path="game.py", content="...")

[input]
- User: Pythonで〇×ゲームをgame.pyに作って
- AI: 作るね
- AI: write_file(path="game.py", content="...")
- Tool: success

[output]
- AI: 書いたよ。動くか確認するね
- AI: run_command(command="python game.py")

[input]
- User: Pythonで〇×ゲームをgame.pyに作って
- AI: 作るね
- AI: write_file(path="game.py", content="...")
- Tool: success
- AI: 書いたよ。動くか確認するね
- AI: run_command(command="python game.py")
- Tool: "SyntaxError: invalid syntax (game.py, line 12)"

[output]
- AI: エラーがあった。直すね
- AI: str_replace(path="game.py", old_str="...", new_str="...")

[input]
- User: Pythonで〇×ゲームをgame.pyに作って
- AI: 作るね
- AI: write_file(path="game.py", content="...")
- Tool: success
- AI: 書いたよ。動くか確認するね
- AI: run_command(command="python game.py")
- Tool: "SyntaxError: invalid syntax (game.py, line 12)"
- AI: エラーがあった。直すね
- AI: str_replace(path="game.py", old_str="...", new_str="...")
- Tool: success

[output]
- AI: run_command(command="python game.py")

[input]
- User: Pythonで〇×ゲームをgame.pyに作って
- AI: 作るね
- AI: write_file(path="game.py", content="...")
- Tool: success
- AI: 書いたよ。動くか確認するね
- AI: run_command(command="python game.py")
- Tool: "SyntaxError: invalid syntax (game.py, line 12)"
- AI: エラーがあった。直すね
- AI: str_replace(path="game.py", old_str="...", new_str="...")
- Tool: success
- AI: run_command(command="python game.py")
- Tool: ""

[output]
- AI: game.py できたよ！エラーもなく動いてる
```

毎回こんなやり取りをするから、コードエージェントを雑に使うとすぐトークンがなくなるわけである。

そうすると実装したいものがある。`/compact`だ。

仕組みは簡単で、これまでの会話を、それこそ LLM に1行に要約してもらう。

```sh
[input]
- User: Pythonで〇×ゲームをgame.pyに作って
- AI: 作るね
- AI: write_file(path="game.py", content="...")
- Tool: success
- AI: 書いたよ。動くか確認するね
- AI: run_command(command="python game.py")
- Tool: "SyntaxError: invalid syntax (game.py, line 12)"
- AI: エラーがあった。直すね
- AI: str_replace(path="game.py", old_str="...", new_str="...")
- Tool: success
- AI: run_command(command="python game.py")
- Tool: ""
- AI: game.py できたよ！エラーもなく動いてる
- User: /compact

[output]
- AI: 【要約】game.pyを作成。構文エラーが1件あったが修正済み。現在正常に動作する状態。

[input]
- User: 【要約】game.pyを作成。構文エラーが1件あったが修正済み。現在正常に動作する状態。
- User: それじゃあ次のお願い
```

こんなイメージ。理論上、次からの入力が「要約の1行+人間の1行」になる。

けど実際試してみたら、要約の方がテキスト量多くなったりする...... compact のためのうまいプロンプトがいるかもしれない。


## エージェントのほかの活用例を考える

ということで、コードエージェントは作れることがわかった。そのほかのエージェントであっても、用途とそれに合ったツールを用意することで、同じように作れるだろう。  
話が最初に戻るけど、ツールにエージェントを組み込む、またはツールとしてエージェントを作るというのも、まあできなくなさそうである。

じゃあ他には何をさせる？......これがあんまり思いつかない（調べ不足で、もしかしたら既に優れた活用例があるかもしれない）。

向いているタスクとしては、

- ループ会話が必要
- 達成要件がはっきりしている

だと思う。

例えばだけど、「データ分析コンペ」用のエージェントはどうだろう。要件が「データ分析の精度（スコア）を上げる」なので、シンプルな気がする。基本的なノウハウをドキュメントにまとめたり、ネットにある手法を調べさせたり、うまいこと環境を整えてあげると、いい手法の組み合わせを見つけてくれる、かもしれない。

試してはないのだけど...
これまで話した通り、強力な手法だとは思うので、コードエージェント並にハマる領域があるのではないかなーと期待している。

## まとめ

「エージェント」とはこんなもんかと、少し身近なものになったら嬉しい。あとはコードエージェント以外の活用例があったら嬉しいし、すでにあったら教えてください。
